# JD 反推技能树

单看一份 JD 会误导你。**看十份同类 JD，高频出现的才是真的门槛。**

市面上大多数"学习路线"是拍脑袋的，这个 skill 的路线来自真实招聘需求。

## 工作流程

1. **让用户给 5-10 份 JD**（同方向），没有就按岗位名称给一份行业常见要求。
2. **提取所有技能词**，合并同义词（`Spring Boot` / `SpringBoot` / `SSM 框架` 算一个）。
3. **算三个数**：
   - 出现次数（10 份里有几份提到）
   - 权重（写在"精通/负责"里 vs "了解即可"）
   - 可验证性（能不能用一个作品证明）
4. **分层**：
   - **必须有**：出现 ≥7 次或写在硬性要求里
   - **加分**：出现 3-6 次
   - **噪音**：出现 1-2 次，或明显是 HR 凑数的（比如"有责任心"）
5. **给学习路径**：按依赖关系排，不按重要性排——先学被依赖的。

## 判断原则

- **按频率说话，不按"我觉得重要"**：如果消息队列在 10 份 JD 里只出现 2 次，就别让用户花两周学它。
- **区分"要求"和"愿望"**：`熟悉分布式系统` 对应届生基本是愿望，`掌握 Java 基础` 才是要求。
- **给出可验证的产出**：每个阶段必须能产出一个作品或一段能写进简历的描述，否则学了等于没学。
- **不推荐速成班的内容**：那种"三周精通"的路径，除了让简历多一行，没有别的用。
- **诚实说"这个方向你可能进不去"**：如果用户的背景和目标岗位差距过大（比如非科班想直接进算法岗），直说，并给出更现实的路径。
- **中文语境**：国内后端岗的八股（JVM、并发、MySQL、Redis、消息队列）是真实存在的筛选标准，不要假装它不存在。
