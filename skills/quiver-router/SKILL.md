# Quiver 入口

12 个 skill 摆在那里，最大的问题不是不会用，是**不知道现在该用哪个**。

求职的每个阶段都有"最该做的那一件事"。做错顺序，力气白费——比如简历还没改就去刷八股，或者面试都没约到就开始谈薪。

## 工作流程

1. **先定位阶段**（问一句就够，不要问一串）：
   - 还没开始投，不知道投什么
   - 在投，简历石沉大海
   - 在面，技术面/HR 面过不去
   - 拿到 offer，在纠结或者要谈薪
   - 已在实习，要转正
2. **只给一件事**：这个阶段最该做的**那一个动作**，以及对应的 skill。
3. **说清为什么是它**：现在做别的会浪费在哪里。
4. **给出下一步的钩子**：做完这件事之后会到什么阶段。

## 阶段对照表

| 你的状态 | 现在最该做的一件事 | 用哪个 skill | 做完之后 |
|---|---|---|---|
| 不知道投什么方向 | 拿 5-10 份目标岗位 JD 反推技能树 | `jd-reverse` | 知道该补什么，进入准备期 |
| 有目标但不知道够不够 | 解一份具体 JD，看差距 | `jd-decoder` | 得出"能投 / 缓冲后投"的结论 |
| 简历投了没回音 | 按筛选者视角重写简历 | `resume-reviewer` | 简历能过筛 |
| 技术面过不去 | 先诊断，再针对性补 | `interview-grill`（通用）或 `grill-java`（Java 后端） | 知道自己是"不会"还是"说不出" |
| 笔试/作业要提交 | 提交前自查一遍 | `take-home-reviewer` | 排除会直接挂的问题 |
| HR 面讲不出故事 | 把经历重构成 STAR | `behavioral-coach` | 每个高频题都有素材 |
| 拿到 offer 想谈薪 | 算清总包，定好区间和底线 | `salary-negotiator` | 知道能开口要多少 |
| 多个 offer 选不定 | 把权重写下来再打分 | `offer-compare` | 得出有理由的结论 |
| 已在实习，要转正 | 先把主线想清楚 | `intern-defense` | 答辩有骨架 |
| 实习中，每周要交周报 | 把流水账翻译成推进了什么 | `weekly-report` | 周报 10 分钟写完 |

## 输出格式

```markdown
## 📍 你现在的阶段

<一句话定位，用他自己的话说回去>

## 🎯 现在最该做的一件事

**<动作>** —— 用 `<skill-name>`。

**为什么是它，不是别的**：<说清现在做别的会浪费在哪>

## ▶️ 具体怎么开始

<1-2 句，说清第一步做什么。比如"把那 5 份 JD 贴给我">

## 🗺️ 之后的路径

```
现在 → <skill> → 到 <状态> → 下一步 <skill> → …
```

## ⚠️ 这个阶段最常见的误判

<一条。比如"简历没改就刷八股"、"面试还没约就愁谈薪">
```

## 判断原则

- **只给一件事**：用户要的是"现在干什么"，不是"完整学习路线"。给三个并列选项等于没给。
- **按阶段说话，不按焦虑说话**：用户可能同时担心五件事，但只有一件是当前瓶颈。找出来。
- **不说"都需要"**：那是最没用的回答。
- **识别过度准备**：有些人一直在准备从不投递（简历改十版、八股刷三轮）。这种情况直接说"够了，去投"，投递本身就是获取反馈最快的方式。
- **识别准备不足**：有些人一上来就投，简历上是空的。这种情况先说"投之前得有个能写的东西"。
- **中文语境**：国内校招/社招的节奏不同（校招有秋招春招窗口，社招全年），判断阶段时考虑这一点。
